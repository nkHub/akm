# 版本变更记录

## v0.1.59

**修复 Agent 自测报告暴露的四个回归**（35 个探测点 / 30 通过 / 1 致命 / 2 轻微，均为 v0.1.58 引入）。只改 `akm/agent_runtime/tools.py`、测试与文档，无对外工具签名变化，无新增模板 / 静态文件。

1. **P0：GB18030 等非 UTF-8 文件的 tag 死锁**——`akm_read_file` 用「解码成 `str` 再 `.encode('utf-8')`」算 tag，而 `akm_edit_file` / `akm_write_file` 的校验路径用「原始字节 `.decode('utf-8', errors='replace')`」算 tag。同一个文件两条口径两个哈希（`测试二` 得到 `D94C` vs `C1E9`），纯 UTF-8 文件恰好相等所以测试全过，GB18030 / GBK / Latin-1 文件则永久死锁：**读得到、改不了**，重读也救不回来（read 永远给一个值、校验永远要另一个值）。修法是把 tag 收敛成**唯一一条字节口径**：`_content_tag()` 只接受 `bytes`，`_file_tag()` / `_record_observation()` 的输入要么是调用方已持有的原始字节、要么自己 `read_bytes()`（>8MB 走 `size ^ mtime_ns` 指纹），read 与校验调的是同一个函数、同一份输入。
2. **同一处连带的编码破坏**：v0.1.58 写盘一律用 UTF-8，覆盖一个 GBK 老文件会把它整体转码，用户在别的编辑器里看到满屏 diff 甚至乱码。现在 `_atomic_write_text(target, text, encoding)` 接受目标编码并**返回实际使用的编码**，`write`（覆盖/追加）与 `edit`（行号/内容两种模式）都按原文件编码写回；编码表示不了新内容时回退 UTF-8，并在结果里给 `encoding` / `encoding_changed` / `notice`。解不干净的文件（二进制或未知编码，`_decode_text_bytes` 返回 `utf-8(replace)`）**拒绝 edit**——行号与锚点编辑在乱码上改必然写坏文件；`write` 仍允许，因为那是模型显式声明的整体内容。
3. **P1：敏感名单在 shell 侧形同虚设**——文件工具层拦住了 `.env` / `id_rsa` / `.git/config`，但 `akm_run_shell` 里 `cat .env .git/config id_rsa` 三条全成功。现在 seatbelt profile 在 `(allow file-read*)` **之后**补上工作区内敏感文件的 `(deny file-read-data (regex ...))`（SBPL 是 last-match-wins，写在 allow 前面等于没写），名单直接复用 `_WORKSPACE_SENSITIVE_NAMES` / `_WORKSPACE_SENSITIVE_SUFFIXES` / `_ENV_TEMPLATE_SUFFIXES`，`.env.example` 这类模板在 deny 之后再放行。只 deny `file-read-data` 而不是 `file-read*`：后者会把 `ls` / `stat` 一起打掉、刷一屏 `Operation not permitted`，而真正要防的只是「读到密钥内容」。`.git` 不 deny（文件工具层已拦）。同时修掉一个更隐蔽的坑：profile 里的工作区、家目录、`TMPDIR` 路径原先未解析，而 macOS 上 `/var`、`/tmp`、`/etc` 都是 `/private/*` 的符号链接，工作区落在 `TMPDIR` 或 `/tmp` 下时所有 `subpath` allow 都会失配——既写不进文件（fail-close），新加的敏感 deny 也一起失效（fail-open，`.env` 反而能读）。现在统一 `os.path.realpath`。
4. **P2-1：大文件截断时总行数错**——`_collect_window()` 在字节预算超限时直接 `break`，`total_lines` 停在被截断的那一行，于是 5000 行的文件在 60KB 窗口处报「共 1225 行」，模型以为已读到结尾，后面的内容直接丢失（`offset=1224` 重读才报对 5000）。现在超预算只停止**收集内容**，仍继续数完真实行数。
5. **P2-2：`.git` 的拒绝文案指向不存在的工具**——旧文案写「请用 `akm_run_git`」，但 `agent_git_enabled=false` 时该工具根本没注册，等于让模型去调一个不存在的工具。改为中性提示：「位于版本库内部目录 `.git/` 下，文件工具不直接访问；如需操作版本库，请先开启 `agent_git_enabled` 再用 `akm_run_git`」。

**验证**：`pytest` 全量 1409 项通过，其中 `tests/test_agent_workspace_tools.py` 新增 7 项针对性用例——GB18030 文件 `read → edit` 全链路（tag 一致且写回仍是 GB18030 字节）、未知编码拒绝 edit、write/append 保持编码、5000 行文件截断时 footer 报真实总行数、`.git` 文案、seatbelt profile 的 deny 位置与 realpath、以及**真实执行**沙箱后被拒 `cat .env id_rsa` 而 `cat .env.example` 正常。

**已知边界（本次未改，勿误读为安全边界）**：① 敏感名单在文件工具层是**硬拦截**，shell 侧只在 `agent_run_shell_sandbox=true` 时有同口径 deny，关掉沙箱即失效；② shell 内的 `git` 仍不可用（`/etc/gitconfig`、`~/.gitconfig` 在家目录/系统目录 deny 列表里），需要用 git 请走 `akm_run_git` 或关沙箱，这是 v0.1.58 之前就有的行为；③ `akm_delete_file` 同样受敏感名单拦截，`.env` 之类删不掉，需要清理只能走 shell 或手工操作——这是有意的，避免模型顺手删凭据。

**审计日志「供应商」列修正：本地工具调用记录不再写死 `akm`**：用户反馈「Key 列表里 `command` 明明是 `commandcode` 供应商，为什么日志里同一批请求的供应商列写 `akm`」。排查确认是**写库口径**问题，不是展示层：`_submit_tool_call_audit()`（`akm_render` / `akm_fetch_url` 等本地工具调用的记录）把 `provider` 硬编码成应用名 `akm`，而同一行的 `model` / `key_alias` 取的却是 AgentLoop 注入的真实值——于是落下「Key 属于 A 供应商、供应商列写 akm」的自相矛盾记录，日志页的供应商筛选下拉里还会多出一个没有对应 Key 的 `akm` 选项。修法：审计上下文 `set_request_audit_context()` 新增 `provider` 字段，`AgentLoop._execute_registered_tool()` 从本轮上游结果 `result["provider"]` 取值注入，工具调用审计改用它；拿不到上下文时留空，**绝不写死应用名**。工具名仍留在 `x-akm-tool` 头里、来源标签仍是 `Chat Tool` / `Task Tool`、token 全 0 不进成本统计的口径一律不变。**验证**：`pytest tests/test_render_schema.py tests/test_agent_fetch_url.py tests/test_agent_loop.py tests/test_agent_tools.py tests/test_agent.py tests/test_agent_layout.py` 共 227 项通过——新增断言「上下文里给了 `provider` 时，审计记录的 provider 列等于它」，并把「没有上下文时留空（而不是 `akm`）」钉进两条旧用例。**已知边界**：历史日志按写入当时的字段落库、不会重算，旧记录仍显示 `akm`，重启后新请求才正确；如要回填可自行执行 `UPDATE audit_logs SET provider=(SELECT k.provider FROM keys k WHERE k.alias=audit_logs.key_alias) WHERE provider='akm' AND key_alias<>''`（本次未自动执行，避免擅改用户数据）。
**添加 Key 的供应商下拉：「自定义…」提到最前**：原候选顺序是「未选择 → 自定义供应商 → models.dev 目录（200+ 条）→ 自定义…」，想手填供应商名得滚到列表最底部。现改为「未选择 → 自定义…（手填供应商名与 Base URL）→ 自定义供应商 → models.dev 目录」，只调 `akm/templates/keys.html` 里候选的拼装顺序，`akm-combobox` 组件与分组标题渲染逻辑未改。

**桌宠回调 AKM 时显式置空 `User-Agent`，修掉被 Cloudflare Error 1010 拦截的 403**：用户反馈桌宠每 3 分钟一次碎碎念全部失败，审计里 `status_code` 是 502。顺着流图查到真正的第一跳是上游 `api.commandcode.ai` 返回 **403 + Error 1010**（`banned your access based on your browser's signature`），不是超时也不是上游 5xx——请求到了 Cloudflare 并被主动拒绝。根因在两层叠加：`plugins/dafeiyu/pet/companion.py` 的 `call_chat()` 只设了 `Content-Type`（和可选 `Authorization`），urllib 于是自动补上 `Python-urllib/3.12`；而 `~/.akm/config.json` 开着 `use_native_user_agent`，`akm/agent.py` 的 `_resolve_user_agent()` 会把客户端 UA **原样透传**给上游。这个默认 UA 是 WAF 的典型爬虫特征，必然被拦。修法是在 `call_chat()` 里 `headers["User-Agent"] = ""`：urllib 见该头已存在便不再补默认值，AKM 侧 `original_user_agent` 为空，按既有逻辑回退 `akm/<version>`——与「客户端压根没带 UA」完全同语义，也不用在插件里硬编码版本号（避免 AKM 升级后漂移）。只改这一个文件，未动内核、未改 `use_native_user_agent` 默认值（那个开关是给 pi-desktop / codex 这类需要身份头的客户端用的，关掉影响面更大）。**验证**：本地起 HTTP server 实测 urllib 三种情形——不设 UA 得到 `Python-urllib/3.12`、置空得到空串、显式值原样保留；再直接调 `Agent._resolve_user_agent("", "")` 确认返回 `akm/0.1.59`；`pytest tests/test_dafeiyu_companion.py` 35 项通过。**已知边界**：① 审计日志的来源标签会从 `Python` 变成 `未知`（空 UA 无法归类），要恢复需同时带 `x-akm-source: plugin`，但该头在开启原生透传时会被一起带给上游，故本次没有加；② 只同步了 `~/.akm/plugins/dafeiyu/` 的安装副本与仓库源码两处，桌宠是 `subprocess.Popen` 拉起的一次性进程、没有自动守护，必须手动重启才会加载新代码；③ 碎碎念默认 180s 一次真实模型调用，本次没有改频率。

## v0.1.58

**Agent 工作区读写工具全面对齐参考实现（pi-desktop / DeepSeek Harness）**：`akm/agent_runtime/tools.py` 的读写工具做了五组改造，目标是「模型一次把文件改对」，而不是靠反复试探。

1. **`akm_read_file` 输出改为带行号纯文本 + 版本 tag**：原先返回 JSON（`content` 里的换行被转义成 `\n`，白烧 token 且难定位），且只有 `start_line`、没有行号；`offset` 是 0-based 而 `akm_edit_file` 的 `start_line` 是 1-based，是最容易改错行的错位来源。现在返回 `[路径#TAG]` 头 + `41: def main():` 形式的**绝对行号**，`offset` 统一为 1-based，footer 直接给「继续读取用 offset=N」；默认窗口 2000 行（上限 4000），单次窗口 60KB、单行 2000 字符封顶；编码按 `utf-8 → gb18030` 回退（原先固定 `utf-8/replace` 会把 GBK 文件静默变成乱码，模型看到乱码后往往整文件覆写），前 8KB 含 `NUL` 判为二进制并给可操作错误。
2. **写工具加「先读后写 + 版本校验 + 唯一匹配 + 回显 diff」**：`agent_write_requires_read`（默认开启）要求覆盖/编辑已存在文件前先 `akm_read_file` 过它，否则返回「必须先读取」并附恢复指令；`akm_read_file` 返回的 4 位 `TAG` 可传给 `tag` 参数，与磁盘内容不一致即拒绝（文件被外部改动）；`akm_edit_file` 内容模式的 `old_string` 从「静默改第一处」改为**必须唯一匹配**（多处命中报错要求补上下文或显式 `replace_all=true`）；行号模式新增行区间 provenance（只允许改本会话读过的行）；成功后返回新 `tag` 与 unified `diff`；`akm_edit_file` 补上全文大小预检（原先直接 `read_text` 整个文件，与 read 的 50MB / write 的 10MB 口径不一致）。
3. **`akm_grep` 每个文件返回全部命中行**：原先命中第一条就 `break`，同文件其余命中被静默丢弃，模型只能反复换 pattern 试探；现在按 mtime 倒序扫描、每文件全量命中，新增 `include`（glob 过滤）、`output_mode`（`content`/`files_with_matches`/`count`）、`head_limit`（默认 100，上限 4000），并在截断时返回 `truncated` + `notice`（原先 `total` 恒等于返回条数，模型看不出被截断）。`akm_glob` 也改为 mtime 倒序 + `limit`（默认 100，上限 1000），并修掉「`matches` 到上限但 `truncated=false`」的误导；`akm_list_dir` 支持 `offset`/`limit` 分页与 `next_offset`。
4. **敏感文件名单位置统一拦截**：新增 `agent_sensitive_path_guard`（默认开启），在 `_safe_resolve_workspace_path` 一处拦截工作区内的 `.env`（模板除外）、`id_rsa` 等私钥、`credentials.json`/`.netrc` 等凭据、`*.pem`/`*.key`/`*.p12` 等证书、`.git` 目录内部文件；原先只有 shell 侧 seatbelt 有黑名单，文件工具可直接读工作区里的 `.env`，等于绕过隔离。grep/glob 遍历同样跳过敏感文件。
5. **补齐工具面与可观测性**：新增 `akm_move_file` / `akm_copy_file`（原先挪一个文件要 read+write+delete，既费 token 又丢权限位），`akm_delete_file` 返回 `entries_removed`；工作区工具补上**工具调用级审计**（原先只有 `akm_render` / `akm_fetch_url` 有，真正改磁盘的工具反而没有），`build_workspace_tools(app)` 接 app 并可用 `agent_tool_audit_enabled` 关闭；同一路径的写/编辑用 asyncio 锁串行；`ToolDef` 新增 `max_result_chars` 结果预算（`shell`/`grep`/`glob` 100–200KB，超出按首尾保留中间省略，`akm_render` 的 layout JSON 不受影响）。

**`agent_chat` 前端协同改动（未发插件市场版）**：chat 是显式传 `tools` 走白名单的（`resolveDeclaredTools`），服务端只注入调用方声明过的工具——后端加了 `akm_move_file` / `akm_copy_file` 而前端不声明，等于白加。改动四处（前端仓库 `/Users/nk/Desktop/Ecology/chat`）：① `src/lib/agent-api.ts` 的 `resolveDeclaredTools()` 用两个新工具声明**替换掉已下线的 `AKM_XLSX_TOOL`**（`akm_xlsx` 后端早已移除，前端只留死声明）；② 同文件 6 个内联 schema（read / list_dir / glob / grep / write / edit）文案对齐新契约——尤其 `akm_read_file` 的 `offset` 从「0 开始，默认 0」改成「1-based，默认 1」，write/edit 补 `tag` 参数，grep 补 `include` / `output_mode` / `head_limit`（这些内联 schema 执行时会被服务端同名定义覆盖，但后端未注册该工具时（如未配 `agent_workspace_root`）会原样下发给模型，属于必须对齐的文案债）；③ `src/lib/step-labels.ts` 的 `TOOL_LABELS` 增加「移动文件 / 复制文件」并删掉 `akm_xlsx`，否则时间线里裸露成 `akm_move_file` + 扳手图标；④ 同文件 `summarizeStepResult` 新增 `summarizePlainTextResult`，跳过 read 结果里的 `[路径#TAG]` 头、`N: ` 行号前缀与中文 footer——新 read 首行以 `[` 开头会被误判成 JSON 数组，`JSON.parse` 失败后回落取第一行，摘要就变成 `[hello.txt#6FA7]` 这种 tag 而不是内容首行。

**取价改为三段式 + 官方兜底开关**：`akm/cost_estimate.py` 新增 `PriceResolver`，按 `cost_pricing_source` 三档工作——`manual`（只用现有手写表，与历史行为逐字节等价）、`snapshot`（**新默认**：① key 的供应商存在且名下有该模型 → 用它在该供应商下的价；② 不匹配时按 `models_dev_prefer_providers` 原厂顺序兜底，受新开关 `models_dev_official_fallback`（默认开）控制；③ 都失败按 0）、`hybrid`（手写表优先 → 三段式 → 0）。手写表的匹配改为「精确 dict + 通配列表」索引，并用 3200 次随机比对证明了与旧 `match_price` 的「按书写顺序首个命中」语义**完全等价**（含重复精确行取第一条、`*` 兜底为 `1/1/3`）。四处消费点（首页统计 `_get_stats`、`/api/logs`、`akm_get_usage_stats` 工具、`budget_gate` 插件）统一改走 `PriceResolver`，并在统计缓存键里加入 `cost_pricing_source` / 兜底开关 / 原厂顺序，避免切换数据源后仍展示旧费用。**费用口径变化实测**（本机 30 天 27110 行日志）：`manual` $366.99、`snapshot` + 兜底 $492.00（命中率 89.7%）、`snapshot` 关兜底 $63.17（命中率 62.2%，其余因供应商/模型对不上而归 0）、`hybrid` + 兜底 $787.17。**升级提示**：老 `config.json` 没有 `cost_pricing_source` 键时会补成默认值 `snapshot`，此时原手写表不再参与计价；需要保留原有手写口径请在设置页把「取价数据源」改为「仅手写单价表」，或直接在 `config.json` 写 `"cost_pricing_source": "manual"`。`akm_get_usage_stats` 在非 `manual` 模式下只回取价口径摘要（不回几千条全量规则，避免撑爆上下文）。

**审计日志新增「换模型检测」**：`audit_logs` 增加 `response_model TEXT`（上游**原始响应**里的 model 名）与 `model_mismatch INTEGER`（`NULL`=没取到 / `0`=一致 / `1`=被换，三态严格区分，避免"没证据"被统计当成"干净"）。流式侧复用在用的 `_IncrementalSSEUsageTracker`（本来就在逐行解析 SSE 取 usage），`_state` 加 `model` 字段后零额外开销；非流式从 `result["upstream_response_body_for_log"]` 提取——**必须取转换前的那份**，`result["body"]` 是协议转换后给客户端的内容，转换器可能重写 `model`，从那里取会误报。比较前归一（小写、去 `vendor/` 前缀、去日期/版本后缀），避免 `deepseek/deepseek-v4.1-flash` 与 `deepseek-v4.1-flash` 这类无害差异误判。日志页在模型名后显示 `⇄` 并悬浮给出「请求 X → 实际 Y」，顶部新增「换模型」按钮只筛 `model_mismatch=1`（`/api/logs` 新增 `mismatch=1` 参数），筛选状态随其它筛选一起持久化。

AG-UI 卡片暗色适配（chat 界面）：暗色下自绘卡片（stats / cards / kanban / alert / progress / map / chart）仍是浅底白卡，「Tool 总数 44」这类指标卡是 `bg-blue-50` 的亮底，kanban 卡片是 `bg-white` 的白底，而卡内标题用的是 `text-muted-foreground`（暗色下是浅灰）——浅灰字压在白底上基本看不见。根因分两类：①映射表驱动的配色只写了浅色档（`bg-*-50` / `text-*-700` / `border-*-200` / `bg-white`），没有 `dark:` 对应值；②recharts 的配色是**写死的 hex**，而 SVG 的 `fill`/`stroke` 是 presentation attribute，**不接受 `var()`**（写成 `fill="var(--chart-1)"` 会被浏览器忽略、整块变黑），所以图表色不能简单换成 CSS 变量。修法：①所有映射表补齐 `dark:` —— `BG`/`STAT_COLOR`/`BADGE_TAG_COLORS`/`ALERT_STYLES`/`TIMELINE_DOT`/`KANBAN_PRIORITY`/`KANBAN_COL`/`PROGRESS_COLORS` 统一为「`bg-*-50` → `dark:bg-*-500/10`、`text-*-700` → `dark:text-*-300`、`border-*-200` → `dark:border-*-500/30`」；②卡片壳 `bg-white` → `bg-card`（语义色，暗色自动跟 `--card`）；③地图 4 套 × 6 档热力色阶改成「暗色同色相、不同透明度的叠层」（`dark:bg-*-500/10 → /85`），避免暗底上摆一排实色块，同时保证深浅单调；④图表改用 tailwind 的 `stroke-chart-N` / `fill-chart-N` 类（CSS 才能吃到 `.dark` 下对 `--chart-*` 的覆盖），`theme.css` 新增 `--chart-6`（浅色紫 `oklch(0.55 0.2 300)`、暗色青 `oklch(0.65 0.15 195)`）并把 `--color-chart-6` 登记进 `@theme inline`；轴标签 `fill: "currentColor"` + `className: "text-muted-foreground"`（currentColor 是合法 attribute，颜色仍由 CSS 类给），图例 `wrapperStyle.color: var(--muted-foreground)`，网格线固定 `rgba(148,163,184,0.35)`、tooltip 走 `var(--popover)` / `var(--border)` 内联值。**注意**：模型可通过 `series[].color` 自带颜色，此时只给 SVG attribute、不给 className，避免 CSS 覆盖掉模型指定的色。验证：`npx tsc -b`、`npm run build`、`npm run check:timeline`（46 项）通过；另用构建产物的真实 CSS 做了一张 `.dark` 预览页，逐块比对 — stats 四色卡变深底亮字、cards 透明底带边框、alert 深底细边、kanban `bg-card` 深底 + 黄/红优先级徽标、地图色阶单调递增、图表 6 色明亮。**已知边界**：地图高 3 档（`/45`、`/65`、`/85`）色相差小，暗色下主要靠明度区分；纯前端改动，`plugins/agent_chat/dist` 已重建并同步到 `ccs/plugins/agent_chat/dist` 与 `~/.akm/plugins/agent_chat/dist`，未重新打包 App（刷新即生效）。

`/v1/agent` 新增**客户端工具执行协议**：能力的数据或句柄只存在于客户端本地时（浏览器 IndexedDB、编辑器缓冲区、桌面窗口等），不再需要在服务端写 Python 工具。客户端在请求里声明工具——**推荐顶层 `client_tools` 字段**（与 `tools` 相互独立，因此「只声明自己的客户端工具」不会因为传了 `tools` 而丢掉服务端的默认工具注入策略），也兼容给 `tools` 里的声明加 `"x-akm-client-tool": true`；服务端把声明一并下发给模型（标记字段在注入上游前剥掉，避免未知字段被严格校验的供应商拒绝）但**不注册 handler**，模型调用时本轮编排中断、把调用交回客户端（流式 `client_tool_call` 事件 / 非流式同名字段，`data` 含 `tool_call_id` / `name` / `arguments` / `messages` / `turns` / `usage`，`messages` 已含本轮 `tool_calls` 与已执行完的服务端工具结果），客户端本地执行后把 `role: "tool"` 结果追加入 `messages` 重新请求，同一轮 Agent 从该结果继续——与 `akm_ask_user` 的续跑约定同构。**同名规则：服务端已注册的工具优先**，命中 `ToolRegistry` 的名字一律按服务端工具处理、客户端标记被忽略并记警告，避免客户端静默替换服务端实现，保证审计日志里的工具名始终代表真实执行方。**授权**：客户端工具名一律进本次请求的授权名单（否则模型伪造未声明名字即可触发客户端执行），而未注册又没打客户端标记的声明**不进**名单——只传 schema 拿不到执行权，维持「服务端只读」的安全默认，模型调用它只会拿到一条带修复提示的 `工具未获本次请求授权` 结果（此前这条路径会退化成无法定位原因的 `未找到工具`）。非流式 `run` 与流式 `run_stream` 的工具注入与授权判定合并到 `AgentLoop._plan_tools` 一份实现，新增 `x-akm-client-tool` 标记常量。

内置聊天界面（`agent_chat` 插件，`dist/` 已重建）以 `ui_list_sessions` / `ui_load_session` 两个客户端工具直接从浏览器 IndexedDB 读会话历史。实测模型仍会调用服务器端旧工具 `akm_load_session`，因此彻底移除服务端会话历史链路（不再配置、不再写盘、不再注册工具）；会话历史只由浏览器持有。

聊天界面侧同时给会话历史工具加了**规模约束**，因为用户侧对单会话消息数不做硬上限（实测有 1700 条的会话），全量读取会把上下文和界面一起拖垮：`ui_load_session` 合并为「列表 / 搜索 / 读页」三合一入口——传 `query` 时在所有会话里搜索并返回命中片段与 `offset_from_latest`，传 `name` 时读**一页**消息（`offset 0` 为最新一页，**从最近往前翻**，单次最多 50 条、默认 20 条，返回 `total` / `has_more` / `range` 供翻页），两者都不传则等同于列出会话元数据。`limit` 在实现层被夹紧到 `[1, 50]`，模型要多大都不会一次拉全量；搜索命中总数单独统计、只回传 20 条（`truncated` 标明还有更多），且**优先保留最近的命中**——正序扫描会让 1700 条会话里最早的 20 条命中占满配额、把用户真正关心的近期记录全截掉。分页与搜索的纯逻辑抽到 `src/lib/session-history.ts` 并用 `npm run check:history`（esbuild 打包 + node 断言，26 项）覆盖边界：翻页不重不漏、`offset` 翻过头收敛到最早一页而不是给出空页、逐条夹紧。系统提示词同步加入检索纪律：**不要大量读取聊天记录或试图读完整个会话**，先 `ui_list_sessions` 了解有哪些会话、再用 `query` 定位、只读相关的一两页，且只在用户明确要求回顾历史时才查。

**循环次数配置真正生效**：`agent_max_turns` 本来就是配置项，但聊天界面在请求体里硬编码 `max_turns: 50` 把它覆盖掉了，改配置完全不生效——这是本轮修掉的一个真实回归。前端不再覆盖（传 `0` 表示沿用服务端配置），`AgentLoop` 也从「构造期缓存」改为**每次请求实时读配置**，因此界面上改完下一次请求即生效、不必重启；默认值 100 → 200（即「放大一倍」），归一化夹到 `[1, 2000]`。另新增 `GET /v1/agent/config`（同 `GET /agent/config`），返回当前生效的 `max_turns` / `max_context_tokens`，让客户端发现配置而不是重新写死一份。注意用户 `config.json` 里若已存有 `agent_max_turns: 100`，它现在才第一次真正生效——想要 200 需在配置里显式改。

**旧会话目录清理**：Agent 请求现在完全不写入 `~/.akm/agent_sessions/`；自动保存与会话保留期/文件数配置均已删除。为处理旧版本遗留数据，`run_auto_maintenance()` 在更新包缓存清理开启时会检测 `agent_sessions/`，存在就永久递归删除，不留备份；清理在启动/系统唤醒维护时执行，不在聊天请求路径上执行。

**服务端会话历史工具移除**：原 `akm_list_sessions` / `akm_load_session`（读 `~/.akm/agent_sessions/` 磁盘快照）已整体删除，连同它们的 handler 一并移除。触发原因是一个实测故障：客户端工具接上后模型**仍然**调用了 `akm_load_session`——两套会话工具同时在工具列表里，模型挑了名字更眼熟的那个，于是读到的不是用户当前正在聊的历史，而是服务端落盘的旧快照（协议接上了、数据却是错的）。修复不是「让提示词更用力」，而是让错误选项不存在：权威副本在客户端浏览器（IndexedDB），服务端就不再提供这套工具。旧版会话目录不再使用；更新包缓存清理开启时会清除遗留目录。新增回归测试 `test_builtin_session_tools_are_not_registered` 防止它们被重新注册回来。

**兼容性**：`client_tools` 是新增可选字段，不传时行为与旧版一致（未注册声明的授权判定收紧属修复——那种声明本来也无法执行，只是报错信息更难定位）；Agent 会话落盘实现已整体移除；旧配置键会在读取或保存配置时丢弃。`plugins/agent_chat/dist/` 被 `.gitignore` 忽略、不进发布包，打包前需按 `plugins/agent_chat/README.md` 重建。测试覆盖：`tests/test_agent_loop.py`（客户端工具下发与交回、续跑、服务端同名优先、未标记声明被拒、`client_tools` 不改变默认注入、同名被忽略、轮次上限实时读配置与夹紧、配置驱动轮次生效）、`tests/test_agent_router.py`（`client_tools` 透传与非法 JSON、`/v1/agent/config` 的取值/夹紧/双前缀）、`tests/test_cleanup.py`（更新包维护时删除遗留 `agent_sessions/` 目录）、`tests/test_agent_tools.py`（会话工具确实不再注册），前端分页/搜索另有 `npm run check:history` 的 26 项断言。`akm/agent_runtime/agent.md` 新增「客户端工具执行」「会话历史工具已移除」「运行时配置发现」三节；会话历史只在客户端浏览器保存并更新 SSE 事件表与 `agent_max_turns` 配置说明，`docs/design/plugin-system.md`、`plugins/agent_chat/README.md` 与前端仓库 `README.md` 同步。安全边界提示：该协议让客户端工具跑在用户已信任的边界内（对比服务端 `akm_run_shell` 那类默认关闭 + 沙箱的写工具），但服务端**不校验客户端回传的工具结果**——它能保证「工具名指向的执行方」可信，不能验证结果内容。

## v0.1.52

打包签名从「每次重建都是新身份」改为**可用固定身份固化**，解决「每次启动 AKM 都提示要访问桌面」这一类 macOS 目录授权反复弹窗的问题。**根因**：`scripts/build_app.sh` 以前固定用 `codesign --force --deep --sign -`（ad-hoc），而 ad-hoc 应用的指定要求（designated requirement）是 `cdhash H"…"`——产物内容一变就变，于是每次重建/自更新后系统都把它当成一个**新 App**，桌面/文稿/下载等目录授权要重新询问；实测同一份构建的 TCC 日志只有「放在桌面上直接运行的那个包」触发过 `kTCCServiceSystemPolicyDesktopFolder`，而 ad-hoc 与固定证书签名的指定要求对比是 `cdhash H"ca43a141…"` vs `identifier "com.akm.app" and certificate root = H"02a342de…"`——后者与产物内容无关。**改动**：新增 `scripts/make_signing_cert.sh`（幂等：证书已存在且有效只校验，同名但缺「代码签名」信任设置只补信任，都不重建，避免留下两张同名证书导致签名身份漂移；证书 RSA-2048 / SHA-256 / 10 年、扩展含 `codeSigning`，材料落在 `~/Library/Application Support/AKM/signing`，目录 `0700`、私钥与 `.p12` `0600`、不在仓库内；macOS 自带 LibreSSL 不支持 `openssl req -addext`，故用配置文件声明扩展；`security import` 用 `-A` 换取 `codesign` 免交互，代价是该私钥对本机任意程序可用）；`scripts/build_app.sh` 改为按 `AKM_SIGN_IDENTITY` → 本机自签证书「AKM Local Signing」→ ad-hoc 的顺序选取身份，回退 ad-hoc 时打印告警并说明后果，签名后仍执行 `codesign --verify --deep --strict`；`setup.py` 的 plist 增加 `NSDesktopFolderUsageDescription` / `NSDocumentsFolderUsageDescription` / `NSDownloadsFolderUsageDescription`，让弹窗能说明「为什么需要这个目录」（声明本身不授予权限，仍需用户确认一次）。

**效果与兼容性**：换成固定身份后，应用**第一次启动会再弹一次**目录授权（身份换代，属预期），点「允许」后重建与自动更新都不再询问；从 `/Applications` 还是 `dist/` 启动共享同一条授权记录。没有可用签名身份的机器（CI、其他开发者）行为与老版本一致——回退 ad-hoc 并打印告警，**构建不会失败**；不想生成证书也可以用 `AKM_SIGN_IDENTITY` 指定已有身份。`scripts/build_m1_dmg.sh` 复用 `build_app.sh`，因此 DMG/zip 产物自动带上同一身份。自签身份不等同于 Developer ID 签名或 Apple 公证，分发到其他机器首次打开仍会走 Gatekeeper 提示。本次未改运行时行为，`akm` 代码路径一行未动（`NS*UsageDescription` 是打包元数据）；同时更新了 [docs/design/key-custody.md](design/key-custody.md) 第 10.2/10.5 节——稳定身份消除了「自更新换签名导致钥匙串 ACL 弹授权框」这一风险，改 `secret_backend` 默认值的前置条件只剩「在签名打包后的 `.app` 上跑一遍钥匙串后端」。

该版本不涉及更新管理流程本身（GitHub Release 检查 / 自动更新 / 更新包缓存策略均未变），但提升了自更新后的体验：更新替换 `.app` 不再改变应用身份，目录授权不会因更新而失效。

## v0.1.51

主密钥（`secret.key`）保管加固，新增 `akm/secret_store.py` 集中负责密钥的存放位置、权限与后端。**P0 权限**：密钥文件按 `0600`、密钥目录按 `0700` 创建（`O_CREAT|O_EXCL` 临时文件 + `os.replace` 原子落盘，避免权限竞态与半截文件），读取既有文件时发现权限过宽会自愈并告警，`chmod` 失败只告警、不阻断启动与解密。**P1 位置**：主密钥默认路径从数据目录移到 `~/Library/Application Support/AKM/secret.key`（非 macOS 为 `~/.config/akm`），新增 `AKM_SECRET_DIR` / `AKM_SECRET_FILE` / `AKM_SECRET_KEY` 三个环境覆盖；老位置（数据目录下的 `secret.key`，仍尊重 `AKM_DB_DIR`）作为遗留路径继续被识别，首次读取时**复制**到新路径完成迁移并**保留原文件**以便回滚，新路径不可写时回退使用遗留密钥。**P2 钥匙串（已实现，默认关闭）**：新增 macOS 钥匙串后端，用 ctypes 直连 Security.framework 的 legacy keychain（不用 Data Protection Keychain——实测 `SecItemAdd` 返回 `-34018 errSecMissingEntitlement`，未签名进程不可用），增删改查与回读校验在真机全部通过且无需授权弹框；入口是 `akm secret migrate --to keychain`（复制语义，默认保留明文文件，加 `--purge-file` 才删），默认后端仍为 `file`——应用自更新重新签名后钥匙串 ACL 可能弹一次系统授权框，这一点必须在打包签名后的 `.app` 上验证过才考虑改默认值，本轮无法覆盖。**P3 轮换**：密钥环支持「当前 + 历史密钥」（解密依次尝试、加密只用当前），`akm secret rotate` 轮换主密钥并把库中存量 `api_key` 用新密钥重新加密（单事务提交；解不开的行单独上报为 `undecryptable` 而不阻塞其余 Key），默认保留 1 个历史密钥使旧密文仍可解，`--drop-previous` 可显式丢弃。**清理与防锁死**：`akm secret purge-file`（以及 `migrate --purge-file`）在删除明文密钥文件前逐个比对文件内容是否属于当前密钥环，**内容对不上就拒绝删除**并列出文件名——这是真机全链路验证时暴露并修复的真实缺陷（钥匙串里是密钥 A、明文文件里是密钥 B 时会误删 B）；`purge-file` 还要求 `secret_backend` 已切到 `keychain`（否则明文文件正是配置内的密钥来源）。生成新主密钥是唯一不可逆的动作，因此明文文件缺失时会先用钥匙串里的同一把密钥兜底（覆盖"文件被误删""迁移后把配置改回 `file`"这类会把已有 Key 锁死的路径），确实找不到任何来源才生成；加载阶段若检测到「钥匙串与明文文件不一致」会显式告警，不再静默以钥匙串为准。`akm secret rotate` / `migrate` 会探测本地服务，服务在运行时提示先重启（运行中的进程仍持有旧密钥，重启前不要 `--drop-previous` 或删明文文件）。**观测与配置**：新增 `akm secret status`（`--json` / `--probe`）、`akm doctor` 增加 `master-key` 检查（密钥不可用时报 FAIL）、`config.json` 新增 `secret_backend`（`file` / `keychain`，非法值回落 `file`）。加密格式未变（仍是与 `cryptography.fernet` 互通的 `_MiniFernet`），老密钥文件可直接读取并在首次读取时迁移；未改动 `GET /api/keys/export` 等既有接口；用户手工备份（如 `~/.akm/secret.key.zip`）不被任何流程读取、打包或删除。打包登记：新模块 `akm/secret_store.py` 已加入 `setup.py` 的 `includes`，无新增模板/静态文件。评估过程、真机证据与遗留项见 [docs/design/key-custody.md](design/key-custody.md)。

该版本不改变更新管理策略（GitHub Release 检查 / 自动更新 / 更新包缓存策略均未变）。
