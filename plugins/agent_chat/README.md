# `agent_chat` 插件

AKM `/v1/agent` 的 Web 聊天界面（AetherAI 对话窗口）。构建产物已打进本插件
`dist/` 目录，**启用即用，无需配置绝对路径**。

## 使用

1. 在管理台「插件」页启用 `agent_chat`（或在 `~/.akm/config.json` 的
   `plugin_configs.agent_chat` 中配置）。
2. 访问 `<访问路径>`（默认 `http://127.0.0.1:8800/chat`）开始对话。

界面直接请求同源 `/v1/agent` 与 `/v1/models`，上传的图片等资源走
`/agent-uploads/...` 相对路径，不依赖前端代理。

## 配置

| 键 | 类型 | 默认值 | 说明 |
|----|------|--------|------|
| `route_prefix` | string | `/chat` | 聊天界面挂载路径。不能使用 `/`、`/api`、`/v1`、`/admin`、`/health`、`/debug`。修改后需重启服务 |
| `spa_fallback` | boolean | `true` | 将不存在的无扩展名路径回退到 `index.html`。聊天界面为单页应用，建议保持开启 |

## 过程时间线

助手一轮里的思考与工具调用在前端聚合成一条**可折叠的过程时间线**（不是服务端能力，
无插件配置项）：

- 折叠态只占一行：`7 个步骤 已处理完 6.0s`；进行中显示 `正在处理 · 第 N 步`，有失败步时带红点计数。
- 展开态每步一行：图标 15px 按动作区分（思考=紫脑；读文件 / 写文件 / 搜索 / 联网 / 生图 / 终端 / 子 Agent 各有图标）；
  主标题是人话动作（`akm_read_file` → 「阅读文件」），中间是操作对象 + 结果摘要（等宽小字，单行溢出省略），
  右侧固定 40px 只放状态词（完成 / 进行中 / 失败），所以各行的箭头严格对齐。
- **展开策略**：思考步在生成过程中默认展开（能边想边看），思考结束（段上补齐 `endedAt`）自动折叠成一行摘要；
  工具步始终默认折叠（参数/结果 JSON 信息密度低）。用户手动点过某一步后固定为手动选择，不再被自动策略覆盖。
- 点击某一步仍可查看原始 `params` / `result`；展开状态与耗时随会话存在浏览器 IndexedDB。
- 耗时优先取服务端事件的 `ts` 字段（真实生成时刻），旧服务端没有该字段时回落本地计时。

文案映射与分组逻辑分别是 `src/lib/step-labels.ts`、`src/lib/process-groups.ts`，
改动后运行 `npm run check:timeline`（纯逻辑断言，不依赖界面）。

## 结构化布局（AG-UI）

服务端配置了 `agent_layout_model` 后，助手回答会额外带一份受约束的布局 JSON（`akm.layout` 事件），
前端按 schema 声明的块类型渲染成卡片（指标 / 对比 / 时间线 / 图表 / 待办等）。要点：
- **只暴露 markdown 做不到的块**：schema 里是 `stats / cards / alert / comparison / timeline / chart / progress / kanban / map / separator` 十种；`text / heading / code / table / list` 五种**不下发**（正文的 markdown 已经覆盖），校验白名单仍保留全集以兼容历史卡片。
- **开启即自动补提示词**：`agent_render_enabled` 为真时，服务端会把「什么内容该用卡片、一次 2~3 块、内容多分多次调用」这段指引拼进系统提示（`loop._render_guide()`）；不注入这段，模型基本不会主动调用渲染工具。
- **分次渲染**：单次上限 3 块，鼓励模型分多次调用，卡片随回答逐步出现；每张卡片带 300ms 淡入上移，`prefers-reduced-motion` 下不播。

- 布局只是**增强层**：正文 markdown **始终完整渲染**，卡片作为补充**追加在正文下方**（渲染器第一帧锁定，故不提供「原文 / 卡片」切换 —— 切换等于中途换渲染器）；
- 事件在 `final` **之后**到达：正文先落地、界面立刻收尾，卡片随后补上；生成失败或超时则一直是 markdown；
- 历史消息不会回填布局（只对生成当时的那次回答生效，不占存储升级）；
- 卡片底部**没有**「查看 Layout JSON」入口（`AGUIRenderer` 的 `showDebug` 恒为 `false`），操作区也只保留复制：布局数据只负责展示，调试信息不暴露给使用者。
## 渲染工具模式（推荐）

服务端开启 `agent_render_enabled`（默认关闭）后，会把 `akm_render` 注册为主 Agent 的工具，
组件 schema 与工具描述来自 `akm/agent_runtime/render_schema.json`（唯一真源）。与后置布局模式的区别：

- **时机**：模型在**同一次生成**里直接给出 blocks，卡片在它发生的位置**原位替换**该工具调用；
  不再等回答结束再跑一次布局模型（后者卡片晚到 10~27 秒）。
- **时间线**：渲染工具不进过程时间线，用户只会看到卡片本身，不会看到「渲染界面」这一步。
- **兜底**：`ok=false` / 块校验失败 / 结构不对 → 该段整段不渲染，正文照常显示。
- **互斥**：开启工具模式后，`agent_layout_model` 的后置链路自动跳过，避免同一张卡片出两次。


## 界面布局

- **对话列宽可拖拽**：主内容区（消息区 + 输入框）共用同一宽度与同一套水平 padding。
  左右各一个竖向把手：热区 12px 宽、**只在消息区内**贯穿（不含输入框），视觉是 2px×40px 圆角胶囊（默认透明，
  鼠标进入热区或键盘聚焦才显现，同时拉到 56px 并加深、拖拽变主题色）；支持双击复位与方向键微调；拖任一侧对称伸缩（560–1400px），双击把手复位 896px；宽度存浏览器
  `localStorage`（键 `aether-ai-chat-column-width`）。**容器宽度不足 720px 时把手不渲染**
  （窄屏下列已被压到最小，拖拽没有收益），判定用 `ResizeObserver` 观测主内容区宽度。
- **回到底部**：不在底部时输入框上方浮出 32px 圆形按钮，点击平滑滚到底并恢复吸附。
- **加载反馈**：向上增量加载更早消息显示「正在加载更早的消息…」；首次打开从 IndexedDB
  恢复大量会话时显示底部对齐的骨架（14px 脉动块），不先闪「开始对话」空态。
- **界面减负**：消息不显示头像（助手/用户都不带，正文铺满整列，角色靠左右对齐区分）；
  助手正文不再套卡片外壳（无边框/无背景）；消息操作区默认只有「复制」，
  消息操作区只保留「复制」，hover 才显现（布局的 Layout JSON 调试入口已移除）。
- **过程时间线**：零卡片、无连接线，层级只靠 12px 缩进；图标 15px 弱色并按动作区分
  （读/写/搜/联网/生图/终端/子 Agent），思考步用大脑图标；中间段（操作对象 + 结果摘要）
  在单行内溢出省略（摘要先裁到 300 字符）；**有状态词的行**固定 40px 右对齐、
  **无状态词的行（思考步）直接铺满到箭头**，两种情况下箭头都严格对齐；耗时只出现在组头。
  **渲染类工具（`akm_render` / `render_ui`）不进时间线**：卡片本身已经在正文下方呈现，
  再列一行工具调用只会让人困惑（`HIDDEN_RENDER_TOOLS`，见 `src/lib/process-groups.ts`）。
  以上都是前端行为，**没有任何插件配置项**，也不需要重启服务（刷新页面即生效）。

## 客户端工具与本地会话历史

界面把会话历史存在**浏览器 IndexedDB**（`aether-ai-chat` / `chat-state` / `main`），
服务端读不到。为了让模型也能查询这些历史，界面通过 `/v1/agent` 的**客户端工具执行协议**
自己声明并执行两个工具：

| 工具 | 作用 |
|------|------|
| `ui_list_sessions` | 列出浏览器本地会话（会话名、标题、创建/更新时间、消息数、模型），不含正文 |
| `ui_load_session` | 三合一：传 `query` 搜索全部会话；传 `name` 读该会话**一页**消息；都不传则等同于列出会话元数据 |

**按需取用、不全量读取**：单个会话可能有上千条消息（用户侧不做硬上限），所以
`ui_load_session` 的返回一律有界——分页 `offset 0` 是**最新一页**（从最近往前翻），
单次最多 50 条、默认 20 条，`limit` 在实现层被夹紧，模型要多大都不会一次拉全量；
返回 `total` / `has_more` / `range` 供翻页（`offset` 翻过头会收敛到最早一页，不会给出
空页）。搜索只回命中片段与 `offset_from_latest`，命中总数单独计数、只回传 20 条
（`truncated` 提示还有更多），并**优先保留最近的命中**。系统提示词同时要求模型
「不要大量读取聊天记录或试图读完整个会话」：先列会话、再搜索定位、只读相关一两页。
分页/搜索的纯逻辑在 `src/lib/session-history.ts`，边界有 `npm run check:history` 覆盖
（esbuild + node，26 项断言）。

请求时它们通过顶层 `client_tools` 字段声明（源码见 `src/lib/client-tools.ts`）；模型调用时
服务端下发 `client_tool_call` 事件，界面在浏览器本地执行后按 `tool_call_id` 把结果**回填**进
服务端返回 `messages` 里的占位 tool 消息（`{"status": "awaiting_client"}`）再续跑——不追加新
`role: "tool"` 消息，否则占位 tool 后紧跟第二条 tool 会被 DeepSeek 等严格校验
「`tool` 必须紧跟 assistant `tool_calls`」的上游以 400 拒绝。

**对话历史只保存在浏览器 IndexedDB**：服务端不再落盘 Agent 历史，也不注册读取磁盘快照的
`akm_list_sessions` / `akm_load_session` 工具。两套工具并存曾导致模型选中服务端旧快照而不是
浏览器里的实时记录，因此直接删除了服务端工具与写盘逻辑。旧版遗留的
`~/.akm/agent_sessions/` 会在更新包缓存清理开启时随维护流程永久删除（不备份）；新版本不再创建该目录。

客户端工具协议的完整说明（声明方式、同名规则、授权、续跑约定）见
[`akm/agent_runtime/agent.md`](../../akm/agent_runtime/agent.md) 的「客户端工具执行」。

## 更新界面

聊天界面源码在独立的 [`chat`](https://github.com/nkHub/chat) 项目。更新步骤：

```bash
cd chat
VITE_BASE='./' VITE_AKM_API_URL='' npm run build
cp -R dist/* ../ccs/plugins/agent_chat/dist/
```

`VITE_BASE='./'` 使产物资源引用为相对路径（可挂载到子路径）；
`VITE_AKM_API_URL=''` 使界面请求同源 `/v1/agent`。
